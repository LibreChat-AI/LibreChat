# Authorization model

A Lean 4 model of the shared-link access decision and the generic resource permission gate,
machine-checked properties about that model, and test vectors that Jest runs against the real
middleware with real MongoDB queries. Mutants calibrate the tests.

No Lean is needed to review the tests. Three pieces fit together:

- **Model and theorems** (`Authz/*.lean`). Each decision is a short function; a theorem is a
  statement Lean checks for every possible input. Every file starts with a plain-English summary,
  and each theorem carries a one-line docstring saying what it means.
- **Vectors** (`vectors/*.ndjson`, generated by `lake exe authz_vectors`). Concrete scenarios with
  the model's answer. The Jest specs seed each one into MongoDB, run the real middleware and expect
  the same answer.
- **Mutants** (`mutants.json`). One-line changes that each disable a check in the real code. Every
  one must make a spec fail; a survivor means the specs cannot see that check.

## Claim

For every ACL, group set, share and request in the model, `decideView`, `decideFork` and
`decideResource` satisfy the theorems in `Authz/`. Lean checks them with no `sorry`, warnings as
errors, and only the axioms `propext`, `Classical.choice` and `Quot.sound` (bit-vector lemmas are
closed by the kernel-checked `decide`, not `bv_decide`).

The vectors show that the real middleware returns the model's decision for `decideView`
(`createSharedLinkAccessMiddleware`) and `decideResource` (`canAccessResource`) on every generated
scenario, including rows that must not grant the viewer anything: a grant to another user, to a
role or group the viewer does not hold, a row with no tenant, and a row carrying bit 16. Shared-link
vectors also cover viewers and request contexts from another tenant. Strict tenant isolation
(`TENANT_ISOLATION_STRICT=true`, a separate process because the flag is memoised) keeps every
shared-link outcome. On the resource gate it changes one documented
set: vectors where a viewer with no tenant reaches `checkPermission` (61 today) expect 403, because
`getUserPrincipals` throws without a tenant context and `PermissionService.checkPermission` turns
that into `false`. Production never gets there: `tenantContextMiddleware` rejects such users first.

`decideFork` and the file routes are checked for middleware ordering only.
`api/server/routes/__tests__/share.authz.spec.js` mocks the gate and the handlers' reads; it
shows every share-scoped route sits behind the gate, Continue requires sign-in first, and the
owner-scoped routes reject anonymous requests before reading anything. `effective` is used only by
`single_bit_agrees` and `multi_bit_gap`; no vector tests it against `getEffectivePermissions`.

**Precondition: `DEFAULT_TENANT_ID` is unset.** `getTenantId()` falls back to it, which would turn
every no-context request into a tenant-scoped one. Both conformance tests delete it and probe that
an untenanted query is unfiltered (default) or rejected (strict) before any vector runs.

## Shared-link contract

A share is looked up by its globally unique `shareId` under the request's tenant, then
system-wide when that misses, so a link resolves from any tenant; only a missing or expired share
answers 404. Every ACL read then runs under the share's own tenant. A public grant means "Share
with everyone": it admits every signed-in viewer, whatever their tenant, and anonymous requests
only when `ALLOW_SHARED_LINKS_PUBLIC` is on. Without one, the viewer needs a VIEW grant for
themself, for an in-scope group listing them, or for their role, and the role counts only when the
viewer belongs to the share's tenant.

## Security properties

Most theorems unfold a decision function and pin the model against careless edits; the vectors
and mutants tie those to the code. These say something that could have been false:

- `single_bit_agrees`: for a single-bit requirement, "one row covers the bit" (`hasPermission`)
  equals "the OR of matching rows has the bit" (`effective`). `multi_bit_gap` shows they differ for
  two bits; `packages/api/src/acl/bits.test.ts` keeps every `requiredPermission` literal in
  production source single-bit.
- `foreign_rows_irrelevant`, `share_ignores_foreign_rows` and `resource_ignores_foreign_rows`:
  under a tenant scope, other tenants' ACL rows never change a decision.
- `private_allow_has_grant`: a signed-in viewer allowed without a public grant is backed by a VIEW
  row in the share's scope for their user, an in-scope group containing them, or their role when
  they belong to the share's tenant.
- `cross_tenant_role_irrelevant`: for a viewer outside the share's tenant, the name of their role
  never changes the answer, so a role grant in one tenant cannot admit another tenant's users.
- `context_irrelevant`: the request's tenant context never changes a shared-link decision. A
  header or token naming another tenant neither hides a share nor widens its ACL reads.
- `anonymous_allow_requires_public_flag` and `allow_without_anonymous_flag_is_authenticated`:
  anonymous access needs a public grant and `ALLOW_SHARED_LINKS_PUBLIC`.

Both vector headers also declare the permission bits and principal types the model knows; the
specs pin them against `PermissionBits` and `PrincipalType`, so adding either in TypeScript fails
until the model is extended.

## Mutants

`mutants.json` lists fixed mutants of the modeled code, each naming the theorem it threatens
(checked to exist) and the test that must turn red. `scripts/mutants.mjs` applies one at a time,
rebuilds `packages/data-schemas` when the mutant lives there (its tests load `dist/`), restores the
file on exit or interrupt, and fails if a mutated file differs from `HEAD` afterwards.

## Not covered

- System grants and capability evaluation. `hasCapability` is an input to `decideResource`: the
  specs check that a capability bypasses the ACL and that a throwing capability check does not, but
  not how capabilities are granted.
- The error paths in `AccessControlService` (`checkPermission` and `hasPublicAccess` return `false`
  when a query throws) are never triggered; `PermissionService.checkPermission`'s is reached only
  by the strict-mode untenanted vectors.
- Resource requests whose tenant context differs from the viewer's tenant. `decideResource`
  assumes they match, which `tenantContextMiddleware` enforces for signed-in requests.
- ACL row expiry (`expiredAt` on ACL rows); shares expire through the share row, which is modeled.
- Legacy share rows with `isPublic` (read-time auto-migration); `access.test.ts` covers them.
- What owner-scoped share routes do after sign-in.
- `canAccessAgentFromBody.js` and `fileAccess.js`.
- List endpoints (`findAccessibleResources`); the agent list's query-string filter and insights'
  `VIEW | VIEW_INSIGHTS` use one-row-covers-all semantics, which only narrow a list.
- Principal and group-membership caches: a revoked member keeps access until the TTL expires.
- The `X-Tenant-Id` proxy trust boundary, the UI, rate limits, content filters and file bytes.

## Run

Prerequisites: `elan` on PATH; `npm ci`, then `npm run build:data-provider`,
`npm run build:data-schemas` and `npm run build:api` from the repository root.

```bash
# Proofs; CI audits axioms with lean-action. Appending `theorem t : 1 = 2 := by sorry` to
# Authz/Model.lean must make `lake build` fail.
cd formal/authz && lake build

# Vectors are reproducible
lake exe authz_vectors && git status --porcelain -- vectors   # must print nothing

# Conformance; repeat the two model specs with TENANT_ISOLATION_STRICT=true
cd packages/api && npx jest src/shared-links/access.model.test.ts src/acl/bits.test.ts
cd api && npx jest server/middleware/accessResources/canAccessResource.model.spec.js server/routes/__tests__/share.authz.spec.js

# Calibration, from the repository root with the mutated files committed
node formal/authz/scripts/mutants.mjs [--only <id>]
```

## When a check fails

Vector mismatch: the code changed behavior. Update the Lean definition to match, rebuild, and
treat any theorem that no longer proves as a finding. Mutant anchor moved: the security-relevant
line changed; re-read it, update the model if its meaning changed, then update `find`. Multi-bit
guard: classify the new `requiredPermission` in `bits.test.ts`, or make it single-bit.
